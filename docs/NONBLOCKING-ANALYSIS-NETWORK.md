# Keep navigating when an optional analysis connection fails

A browser journey could stop because an analyst or reviewer connection failed, even when navigation itself remained usable. The new boundary keeps that checkpoint unknown, retains any possible charge, takes a fresh original observation and lets the navigator make a different next decision. It does not replay the missing analyst/reviewer answer, repeat the browser input, invent a finding or create a score.

Only the actual transport catch can set the internal, default-false continuation flag. It inspects a bounded tree of native errors: every leaf must be a known network category or a native internal abort/timeout, with no unknown, TLS, configuration or malformed leaf. Temporary HTTP 408/429/500/502/503/504 replies also qualify. Permanent HTTP/auth errors, malformed JSON, invalid result shape, missing key/approval and money limits remain hard failures. Saved MIXED_CAUSES or OTHER labels cannot recreate this flag or establish the historical exact cause.

ENETUNREACH and EHOSTUNREACH are now safe named network categories for future diagnostics, following the [libuv error definitions](https://docs.libuv.org/en/v1.x/errors.html). They are not added to the strict connection-establishment list for generation retries or zero settlement. Generation replay rules, original request bodies, parent deadlines, request/phase/run/project/routine limits, approval and held charges remain unchanged. The internal continuation flag is not copied into saved diagnostics, and no raw cause, key, URL, address or message is exposed.

The analyst and reviewer are assigned explicitly around their own model calls. A driver error cannot become an analyst error, and SAM is not included in this new recovery. The existing independent optional SAM-outline fallback remains unchanged. Stop, parent abort and an unavailable/changed fresh observation still stop the walk; a hard navigation, source or money failure cannot start extra final model work.

A fresh picture or a wait alone cannot reopen the failed role. It remains deferred until a later canonical performed browser input, linked to its intact stable original capture and matching image hash, advances the walk. The normal next checkpoint can then use that genuinely new evidence. This also prevents finish/final-review paths from silently repeating an uncertain generation. Prepared source reads still pass the original image/hash/full-walk checks before deferral; no source guard is bypassed. A missing review cannot accept a candidate or criterion.

Offline proofs use the actual Runner and model accounting with a mocked provider: an uncertain analyst answer retains its new and historical held rows while the next driver reads a fresh original and the complete earlier walk/notes. Failed review, same-checkpoint deferral, later-input resumption, source changes, parent Stop/abort, failed refresh, permanent/config/schema errors and unchanged generation limits are checked separately. These fixtures do not establish actual website completion, model quality or native reader operation. Parent owns the separately bounded changed-code proof tracked in [ADR-927 (prove safe recovery and usable flight results)](https://linear.app/adrianotrenahi/issue/ADR-927). No real provider/website call, private record/runtime/approval change or new spend occurs in this implementation.

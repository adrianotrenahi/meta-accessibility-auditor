# Recover non-generating count timeouts

The retained public-site attempt stopped when preparing a model request. Its saved diagnostic says input_count, requesting, one attempt and MIXED_CAUSES. That record did not retain the individual categories, so the historical exact causes cannot be recovered from it. An offline aggregate timeout/socket example reproduces the same premature one-attempt stop; it is an example of the defect, not proof of that historical connection's cause.

An input count does not start a model answer. A known internal count timeout, socket failure or fetch cancellation can therefore use the existing maximum of three attempts while the run is active and the parent request signal remains live. The exact body, images, manual-redirect setting, signal and deadline stay the same across attempts. Count retries happen before any new spending reservation or generated answer. Permanent HTTP rejection and malformed JSON do not acquire a retry.

Owner Stop, parent abort and the actual parent request deadline still prevent another attempt. The signal is checked after a failure, before waiting, while waiting, and at the next attempt; the active run is checked before a retry note and before the next request. An internal TimeoutError with a live parent signal is distinct from that parent signal actually being aborted.

Generated answers retain their existing strict connection-establishment rules. A mixed cause, timeout, internal cancellation, socket reset, HTTP response or answer-reading failure does not become a safe generation retry or a claim that no request was sent. An uncertain generation still keeps its one possible charge; historical unknown charges are unchanged. No browser action is repeated by this transport change.

Only MIXED_CAUSES diagnostics add causeCodes: at most sixteen distinct categories from the existing safe allowlist, including OTHER for an unclassified cause. These are observed categories, not an asserted underlying network diagnosis. Original messages, arbitrary codes, IP addresses, URLs, bodies and keys are never copied. Simple and HTTP diagnostics keep their existing shape. The existing thinking feed and Cavioo layout remain unchanged.

Offline fault tests cover identical bodies, successful count recovery, bounded exhaustion, saved safe categories, parent abort/deadline/Stop, malformed JSON, answer-reading timeouts and unchanged generation/held-charge rules. The old deadline fixture is repointed to actually abort its parent signal; its no-retry rule is retained. The actual full-journey and provider recovery proof remains with [ADR-927 (prove safe recovery and usable flight results)](https://linear.app/adrianotrenahi/issue/ADR-927), after review and merge. This implementation makes no provider, website or paid proof call and changes no private records, runtime, approval or spending limit.

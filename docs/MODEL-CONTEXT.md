# Model capacity and spending are separate limits

Muse Spark 1.3 has a documented 1,048,576-token context window, verified on 28 October 2026 at https://dev.meta.ai/docs/models. The same window applies to its Contributor-mode ID, `muse-spark-1.3-contributor`, which the navigator, analyst and reviewer now use (see below); this is a documented setting, not automatic capability discovery. Each role leaves room for its existing maximum output: 4,096 tokens for navigation, 8,192 for analysis and review. Output settings and reasoning effort stay unchanged.

The former 30,000 / 40,000 / 60,000 input ceilings were prototype settings, not the model's capacity. They could stop a populated website before the first action. In the retained Booking.com attempt, the provider counted the complete selected navigation request at 34,655 tokens, but the 30,000 setting stopped it before generation. This change allows that request to reach the existing spending checks with its full selected originals. It does not introduce a mandatory summary or compact navigation view. The original shared records, picture selection and source checks are unchanged; this does not mean the entire website or every historical picture is supplied in every request.

Before generation, the engine counts the exact request, checks input plus reserved output against the documented window, then reserves its maximum estimated cost against the owner's approval, the run, the role and the remaining project allowance. A larger context window does not authorize more money. Unknown charges remain held, requests are not silently retried, and the action, time and request-count limits remain. Each role names its own model and is charged that model's price (`CAPS` and `MODEL_PRICES` in `src/types.ts`). Owner decision, 31 October: navigator, analyst and reviewer use `muse-spark-1.3-contributor`, the same model in Contributor mode at $0.10 per million input tokens and $0.20 per million output tokens, instead of Standard's $1.25 and $4.25: https://dev.meta.ai/docs/pricing-rate-limits. In exchange, Meta may use what is sent and returned (website screenshots, page text, notes and results) to train future models. Contributor mode also allows 150 requests per minute per team, against Standard's 3,000. Journey planning uses the navigator's model; SAM 3.1 has no Contributor mode and is unchanged. Billing reconciliation is still separate from the estimate.

The final review keeps its existing $0.109816 money reserve. That reserve no longer derives from model capacity: deriving it from a million-token request would consume more than the review's entire $0.65 allowance and prevent intermediate reviews. A final request must still fit the money left; the reserve promises no particular amount of evidence can be afforded.

Offline tests check full selected text, focus and control states above all three former ceilings; identical count/generation bodies; context overflow before reservation; run and project refusal before generation; role spending refusal; and the unchanged final-review reserve. These tests use simulated provider replies/counts and spend no credits. Character length is not a replacement for the provider's multimodal token count. A separate exact-boundary driver case admits the request with the standard $3 run budget and refuses it before generation with the smaller $1 owner budget. The retained actual count remains useful evidence about size, not proof of actual navigation or finding accuracy. One bounded actual website journey and recorded-progress proof remains owed before calling this ready.

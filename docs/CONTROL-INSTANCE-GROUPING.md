# One repeated unnamed button, with both original histories

28 October 2026. Offline follow-up above the reviewed live-picture proposal. No earlier paid run is rewritten.

## Impact on the system

The controlled Add button previously produced two cards after its status text changed. The whole-page fingerprint correctly refused to assume that an HTML ID always identifies the same control, but it also separated this unchanged button.

New captures can record an opaque identity for an actual unnamed native button with its own HTML ID. A per-document weak map tracks the actual node: replacing it, cloning it or reloading the page produces another identity even if the HTML and pixels are identical. The map is installed before website scripts and keeps its original map operations. Its protected property adds no DOM attributes or visible content. Only a matching-name candidate's original target is used; an opaque identity never proves an accessible name, keyboard use or spoken output. Extra identity fields are retained only for these eligible unnamed buttons, keeping ordinary controls unchanged.

Grouping across changed surrounding content is deliberately narrow: same run, URL, declared issue, C02 criterion, actual button identity, own selector, unchanged complete button markup, empty exposed name, role, text, type and severity. A replacement node, changed button, malformed or partial identity, different problem or severity remains separate. Other criteria still require unchanged surrounding context. Existing records without these new fields retain their previous conservative grouping rules and first accepted wording.

The new naming group displays the latest complete independently accepted claim and its own review. It never combines an old claim hash with new wording or a different review. Both raw claims, reviews, original images, evidence links and occurrence references remain intact. Withdrawing the later review removes that occurrence instead of borrowing earlier approval. The existing host format exports the exact representative's hashes and anchor plus both original evidence histories; no Cavioo component or layout changes are needed.

Captures also recheck eligible nodes and their markup after taking the picture. An identical replacement during that interval makes the retained capture unstable even when its pixels and accessible state agree. It cannot establish a grouping identity or keep a finding accepted.

## Impact on the system

The fifteen public definitions, permitted evidence and five verdicts live in one versioned source, `src/criteria.ts` (`access-walk/criteria-v1`). Every original captured state gets its required checks before analysis; unanalysed or unsupported states remain owed rather than disappearing. The analyst names the original screen and criterion; the engine binds the exact declared version/scope/check from its pinned read rather than asking the model to invent those links. Analyst proposals and independent reviews bind exact versions, original source graphs and read manifests. Positive results need evidence too. Missing, conflicting, changed or unreviewed evidence remains NOT_TESTED or INCONCLUSIVE. A demonstrated FAIL can remain valid while other checks are incomplete.

The code calculates a score only when all required checks have supported reviewed results. The report additionally withholds any overall score until the run is complete. NOT_APPLICABLE needs its own supported reason; it is excluded from the denominator. A complete synthetic nine-pass/three-fail/three-inapplicable fixture gives 75/100. Finding count, severity and grouping cannot change that calculation. This is a limited journey method, not full Cavioo scoring or accessibility certification.

Every analysed original viewport has six visual-topic entries: content, visual design, layout/composition, affordances, colour usage and consistency/imagery. Missing, duplicate or invalid entries become explicitly unassessed. An examined topic is coverage, not a pass or a finding quota. Visual observations separate the visible premise, interpretation, task concern, recommendation and limits; claims bind an exact observation and original image. The reviewer reads the original walk, notes and images alongside that interpretation. Structural validity does not establish that the interpretation is true.

Browser facts now retain supported contrast values/colours/font details, names/roles, visible and programmatic labels, alternatives/context, target geometry/spacing, titles/headings and message cues, with incompleteness/truncation flags. Numerical contrast follows the appropriate text threshold; image/complex-background unknowns remain unknown. An undersized target is not automatically a failure because spacing and other exceptions matter. See [W3C contrast guidance](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) and [W3C target-size guidance](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html). Visual interpretation also follows public [visual-design principles](https://www.nngroup.com/articles/principles-visual-design/) without imposing a preferred aesthetic.

Missing-fact requests share two slots with native VoiceOver. They can only measure the current verified original, send one bounded Tab, or use the existing real-reader checkpoint. They add no reasoning role or paid retry loop. Stale states and exhausted/native-reserved slots remain untested. A stop during a read consumes no slot; failed execution consumes its slot, preserves any sent input and cannot silently send the same input again. Concurrent requests cannot claim the same original twice. The existing 120-action, fifteen-minute, twenty-driver-request and $3 run limits remain unchanged.

Journey comparisons are narrow original observations. Comparable totals require explicit matching bundle selections, quantities and currency, with a real transition. Ordinary price text and unit prices remain unknown. The current opt-out adapter proves an actual Space attempt on one known, initially checked, explicitly priced checkbox; it does not infer all other paid choices worked. Return proof compares only the approved synthetic email field in Node, retains no value/hash in its comparison observations and clears ephemeral memory. Untested, different or unbound conditions cannot become a hidden-increase or lost-entry finding.

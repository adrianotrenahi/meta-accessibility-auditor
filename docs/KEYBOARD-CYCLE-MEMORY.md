# Remember an observed keyboard cycle

When a real target traversal returns to the same actual control, the next unchanged request must not replay that path merely because the model has made another decision or received another picture. For example, a requested consent button may remain behind a separate two-control offer dialog.

The engine remembers the actual target and cycle-member nodes, their observed dialog membership and relevant focusability state. Evidence names are bounded and scrubbed; no link address, input value or page HTML is added. A repeated refusal cites the first cycle record and its original actions. Each source is identified as a capture or a lightweight focus observation, preserving its original image/action chain. This records a robot limit, never a website keyboard-barrier finding.

The same target can be tried after relevant node, dialog, target-context or document changes, or when an explicit independent key moves actual focus outside the old cycle. Native radio and checkbox selection is read as a boolean, without reading the input value. An already focused target keeps the normal explicitly requested activation path and existing commitment guards. A new capture, unrelated text, changed wording or direction alone does not unlock another traversal. Unknown revalidation sends no input. The engine never dismisses a dialog or accepts consent automatically.

A cycle spanning different dialogs, or a dialog exceeding the control bound, keeps a local conservative refusal using the actual target, participants and observed dialog states. It does not disable the whole run: a verified relevant change can release that refusal. A genuinely failed minimum read keeps the observed document unknown until a verified new document; when its document identity is itself unknown, or cleanup fails, the whole memory remains unavailable. These cases send no traversal input. The fallback never claims that the complete dialog context was inspected.

Memory is bounded by the existing driver limit and owns cloned handles until invalidation or cleanup. A full memory reports that explicit limit rather than forgetting earlier exhausted targets. The shared dialog membership is read once per check; at most sixty controls plus one overflow sentinel are retained from a scope. Runner Stop/final cleanup and page closure release the retained handles; pending reads cannot reopen closed memory. Ordinary explicit single-key actions and all existing input, time, model and money limits remain in force.

Controlled Chromium/WebKit and independent two-dialog proofs establish this behavior only. They do not prove arbitrary website navigation, real reader operation or a completed paid journey. A separate pre-existing commitment-label case found during the independent proof is retained separately; this proposal does not change the rule that blocks booking actions.

# First review decisions

All suggestions were checked independently before changing the code. Duplicate Codex comments describe the same three problems and receive individual replies.

| Finding | Decision and evidence |
| --- | --- |
| CX-001: rewritten title retained unsupported details | Confirmed. Rewrite decisions now stay internal. A complete corrected candidate must receive its own review before publication. The regression test reproduces the old unsupported VoiceOver detail and proves it never reaches the published result. |
| CX-002: a delayed response could show another run's report | Confirmed. Switching runs cancels old requests and invalidates the old update path; rendering also checks the selected run. The real viewer test holds an old response, switches runs and verifies the current report and image remain together. |
| CX-003: native submit labels bypassed the payment boundary | Confirmed. Focused names now come from browser accessibility information, with native input labels as a fallback. Controlled browser tests refuse native Pay now inputs, labels supplied through another element and implicit form submission, without submitting the form. |
| LR-001: phase protection could starve another phase | Rejected. The four phase ceilings sum to exactly $3. When each phase stays within its ceiling, used money plus every other phase's remaining allowance plus the proposed request cannot exceed $3 if the current phase check passes. An offline test exercises all 24 phase orders using the complete allowances. Blocking an already overcharged phase is correct. |
| LR-002: Stop and final cleanup could overlap | Partly confirmed. Repeated Playwright close is not itself a demonstrated failure. However, stopping during startup could overlap reader cleanup or leave a browser launched after the close request. Cleanup now waits for startup and shares one close operation; tests cover those sequences and save unexpected cleanup failures. No native VoiceOver success is claimed by these simulated lifecycle tests. |
| LR-003: missing original capture could show a later screen | Hardened. The normal store retains every original capture, but the viewer now explicitly refuses a fallback after an original was selected. A controlled missing-evidence response produces an unavailable message and no substituted image. |
| LR-004: a fixed key-count sequence was brittle | Confirmed for task progress. The original missing-name measurement remains valid even if a later action misses a target; that does not establish journey completion. The saved driver now observes the known controlled target after each key before activation. A real browser test adds another focusable link and still reaches the basket correctly. |
| LR-005: two different runs share one VoiceOver checkpoint allowance | Rejected. Each run creates a new VoiceOverProbe, so its counter starts at zero. The two-attempt ceiling intentionally includes unsuccessful checks within the same run. Missing control remains recorded as untested. |
| LR-006: encoded path components escape the static-file root | Rejected as a security failure. URL parsing normalises encoded dot components; encoded separators that remain are literal filename characters. Resolution and the directory-prefix check keep served files within the built client folder. Actual HTTP tests request private and encoded paths and confirm neither the key file nor a system password file is served. |
| LR-007: incomplete responses looked completed in request records | Clarified. The original response already retained the provider's explicit status. Request records now distinguish received, incomplete, invalid-result and completed states while retaining actual billed usage. Mock-provider tests establish the distinction without calling Meta. |
| LR-008: actions could cite another run or a changed same-URL state | Confirmed. Actions and measurements require the original capture from this run. A saved state fingerprint rejects changed page structure, focus or scroll; capture/measurement instability remains explicit. A real browser test opens a dialog without changing the URL and confirms the old source is refused. |
| LR-009: reading one record repeatedly loaded the whole run | Confirmed. Direct indexed lookup now reads only the requested item. Existing integrity and foreign-source tests still pass. |
| LR-010: completed reports kept polling | Confirmed. Final report delivery closes the event stream and polling timer. Opening another run starts a separate, cancellable read. |

Validation after the correction batch includes 23 offline tests, TypeScript, formatting, production build, paired keyboard cases, the extra-focusable-element case, controlled activation/source guards and desktop/320px viewer checks. These checks spend no Meta credits. Actual native VoiceOver operation and paid model quality remain separate, outstanding proofs.

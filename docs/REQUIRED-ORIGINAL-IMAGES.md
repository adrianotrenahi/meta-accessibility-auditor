# Required original pictures and analysis admission

The real Booking.com checkpoints needed four original pictures to support their latest before/after actions and attached measurements. The prototype's three-picture analyst setting refused the complete request. It did not mean navigation received text only, and it did not establish a website defect.

Meta documents a maximum of **50 images per request**, also bounded by the request size and context window. The image limit is configured for the existing Muse Spark model from [Meta's image-understanding documentation](https://dev.meta.ai/docs/image-understanding#multiple-images), verified 28 October 2026. The same documentation names the exact `responses/input_tokens` count as the authoritative way to estimate the complete image/text input. This is a documented setting, not automatic provider capability discovery.

## Current requests

New `original-images/2` reads supply every required original picture, including transitive source pictures. Analysis and independent review may each supply up to the documented fifty; navigation still supplies its current original picture. A mandatory fifty-one-picture group refuses before recording a request rather than dropping a picture to fit. The same guard also applies to a direct read of a saved receipt.

The count and generation use the same original records and image attachments. Their existing full-context, owner, run, role, project, request-count and held-charge checks still decide whether generation can proceed. A larger picture allowance does not authorize more money. Provider context or money refusal remains an incomplete check; it never creates an accepted finding or a pass.

The complete raw walk and navigator notes remain available as original records. Pictures are not combined, cropped, relabelled, replaced with summaries or silently omitted. Every image identity, source link and hash still has to match its exact read. Damaged, unstable, missing or foreign originals remain refusals.

## Historical reads

The old `original-images/1` format remains readable with its original three-image analyst/eight-image reviewer constraints and exact return-baseline exemption. An explicitly omitted pre-typing picture can only remain nonvisual for the exact original, approved return comparison. Historical omitted pictures still cannot receive visual examinations, findings or criterion results. Reads without an image receipt retain their earlier all-selected-pictures meaning. Changed or removed receipts still invalidate saved findings through the existing exact read-hash checks.

New requests do not use that omission. A fresh four-state return comparison now sends all four original pictures to both roles. The historical exemption has its own explicit fixture so testing older records does not force current requests to discard a picture.

## Visual coverage stays honest

The model returns at most eighteen visual-topic rows, prioritising the current viewport. Additional supplied pictures provide original evidence and context; sending them does not establish that every topic was examined. The six-topic ledger is still created for every supplied original. Missing, malformed or conflicting topics remain `not_assessed`. For example, supplying fifty pictures with no returned topic rows yields three hundred unassessed rows, zero findings and zero criterion passes. Output allowances and criterion requirements are unchanged.

## Validation and limits

A read-only reconstruction of the seven retained Booking.com checkpoints reproduces the former three-picture refusal. Each needs four originals. The corrected request supplies all four unchanged pictures through simulated count and generation, preserving the exact original walk/notes and the source database's record checksum. No provider request or website visit is made by that reconstruction. Simulated counts establish admission and unchanged transmission, not actual provider token usage, finding accuracy or successful website navigation.

Regression tests cover four, nine and fifty required originals; refusal at fifty-one; current-picture-only navigation; strict historical bounds; omitted, duplicated, changed and unknown-version receipts; full image/text transmission; context and role-money refusal before generation; original return comparisons; conservative visual coverage; and unchanged existing finding-review/source guards. Current and historical behavior are tested separately. Actual paid analysis, supported findings and the complete public journey remain separate owner-coordinated proofs in ADR-912 and ADR-910.

No Cavioo component, layout, customer browser default or public host field changes. No private source, keys, approvals, local records or original website pictures belong in this public repository.

# Screens and keyboard observations

## Impact on the system

Ordinary Tab movement inside a bounded target traversal records the actual input,
before/after focus and a fresh, guarded `keyboard_focus/1` observation. It does not
take another image or create fifteen more criterion checks when the rendered
page is unchanged. A lightweight observation explicitly says that its linked
image is an earlier page original, not a picture of the newly recorded focus.
It can authorize only another Tab movement. Activation, a new model decision and
analysis still require a fresh full original under the existing input/image guards.
Declared bundle prices, choice states or unknown journey context keep the ordinary
original before/action/after comparison, including its strict C11 evidence.

The optional `meaningful-screen/1` receipt identifies a complete bounded rendered
state separately from its necessary full evidence pictures. Its signature keeps
URL, document, accessible content, visible DOM attributes/values, text, layout,
scroll, images, hover and displayed help strict. Bounded stylesheet rules and
native stylesheet identities also guard rule edits and opaque-sheet replacement;
incomplete rules or font loading disable reuse. Only the active control and its descendants may use their own previously
observed unfocused paint as decoration. Unknown baselines disable reuse; changed
paint on every other control remains meaningful. The lightweight observation separately records the actual active colour,
background and shadow; its linked older image is not a photograph of that focus. Changing content, a modal, menu, viewport,
hover, or a changed/unknown rendered signature takes the ordinary image path.
Animated, embedded or shadow/custom-element surfaces, incomplete image loading and more than 2,500 DOM
nodes conservatively disable reuse. This is not a pixel-equality promise.

Every new full picture stays an immutable capture. A later picture of the same
state refers to the exact primary capture ID/hash, matching state signature,
URL/title and dimensions. The host exports those original hashes and optional
receipts; a compatible reader must land before the exporter. Invalid optional
grouping falls back to separate originals, while core source/image refusals stay
hard. Legacy captures have no receipt and remain separate. No retained run is
rewritten, no original image is deleted and reopening starts no model.

## Impact on the UX

For example, three Tabs across an unchanged page create three original keyboard
observations and zero extra pictures/check scopes. A later necessary full focus
image can be retained as an evidence variant of that page. Opening its cookie
dialog or menu creates another screen state, even on the same URL. The compatible
private reader keeps the existing report and screenshot controls: one screen row
per verified state, with every exact original selectable. Finding pins and key
attempts remain bound to their own actual originals.

Grouped screen count is not raw image/check count. Original criterion scopes,
separate focus evidence, incomplete checks and uncertainty remain. Grouping
cannot turn an unknown into PASS or establish full keyboard/VoiceOver coverage.

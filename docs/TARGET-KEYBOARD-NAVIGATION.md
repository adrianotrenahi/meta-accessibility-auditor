# Reach a named control with actual keyboard input

The earlier navigator spent one model decision on each Tab. On Booking.com this used most of a small test allowance before reaching Flights. A new `focus_target` decision names a unique original control, either its recorded ID or its exact accessible role/name. The robot uses real Tab/Shift+Tab input until that control is focused. A calendar can use real arrows within its current native table/grid/listbox. The model chooses the intent; it does not need to decide every intermediate key.

Every key still uses the ordinary input and safety checks, records its original before-state/action/after-state, captures the page, and keeps the price/choice context observations. Native checkbox activation also preserves the same opt-out observation as individual input. Original walk and notes remain directly available to analysis/review. The existing activity feed publishes a fixed keyboard-path message and each actual key while the path runs; its original freeform model note stays saved but is never substituted for that public message. General freeform notes keep their existing whole-interval privacy hold. No synthesized focus, DOM focus, click or fake successful action substitutes for real keys.

Activation is optional and explicit: `activation: Enter` or `Space` means activate that requested control only after reaching it and checking it again. Default traversal only focuses. A pinned node is checked immediately before activation, after context collection; an identical replacement cannot inherit that check. Ordinary booking/payment/login and implicit-form guards still apply. The website can always change after one browser observation; the result is an input record, never a claim that the business task succeeded.

The path stops on a missing/ambiguous/disabled/replaced control, a focus cycle, cancellation, a meaningful page change or twenty-four keys. Twenty-four is a mechanical bound per target intent; the existing 120 browser-action, twenty-decision, fifteen-minute and money limits remain. Plain noninteractive tooltips may change during focus, while original tooltip pictures/text stay saved. Arrow traversal permits only local checked/selected-state changes in the target's current native grid; changed names, controls, prices or other groups stop it. These comparisons do not declare images equivalent or prove accessibility.

A page that changes while the model decides gets a fresh observation and decision before further input. During a path, one unsent-key refresh is allowed when the original target and actual focused node remain identical, complete ARIA/page content is unchanged, and only focus appearance or viewport bookkeeping differs. The fresh original is kept; no performed input is retried. Exhausting analysis/review's own money/request/final-slot allowance leaves those checks unknown and allows navigation to continue. Global, owner and run money limits still stop the run. Loading can wait up to ten seconds in one explicit wait; a loading page does not establish completed results.

Accessible names are decoded from the original quoted browser representation, so literal quotes/backslashes (including the airport field's quoted Anywhere help) match the actual unique control. Target references and native grid roles are validated. Public typing remains limited to identified search fields; no personal/payment/account values are newly admitted.

## Validation and remaining proof

Real controlled Chromium/WebKit paths cover multi-key traversal, original key/screen retention, one target decision instead of one decision per Tab, explicit separate/combined activation, native roving calendar cells, and current money boundaries. Edge cases cover meaningful page changes, same-looking target replacement, stale decisions, missing/ambiguous/disabled targets, cycles, cancellation, physical action limits, exact quoted names, preserved checkbox observations, unrelated price changes and bounded loading. Deliberate guard removals must fail before source is restored exactly.

A browser-only mixed-input reconnaissance reached applied Madrid–London, 23–25 December 2026 results. It discovered the menu-item Flights role, the complete airport combobox name and the calendar's roving checkbox focus; it did not prove this engine's model-driven or keyboard-only journey. The actual engine test remains separate and bounded after reviews/merges, preserving all original records and historical unknown charges. Cavioo components/layout/customer defaults stay unchanged.
